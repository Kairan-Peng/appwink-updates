AppWink v0.1.39

This release fixes the inline opening-mode selector for file and folder hotkeys.

What's New

  • The complete 72 x 38pt opening-mode control now owns pointer input, so both its application-icon side and chevron side reliably open the menu.
  • Opening-mode controls now reuse the same compact interactive surface style as the rest of AppWink, including shared Light/Dark colors and hover feedback.
  • The native application menu keeps its icons, selected checkmark, keyboard and accessibility semantics, and final Choose Other Application... action.

Install Notes

  • Existing users can install 0.1.39 in place over 0.1.38; bindings, shortcuts, opening modes, order, preferences, and license state remain compatible.
  • Folder opening continues to use macOS's public system-open behavior and file opening continues to resolve the current system default dynamically.

Known Limitations

  • Finder owns default-folder window, tab, reuse, and Space behavior.
  • VoiceOver audio was not rerun for this focused patch; the native pop-up- button accessibility role and menu item semantics remain present.
  • This release publishes the Direct notarized DMG only. MAS purchase/restore and App Store Connect evidence remain separate work.

Verification Scope

  • New menu-construction, action-dispatch, selected-state, and full-control hit target tests
  • Focused opening-mode and shared-interactive-style tests
  • Real pointer clicks on both halves of the file and folder selectors, switching each to Code and restoring system default / Finder
  • Real Choose Other Application... system-panel open/cancel flow
  • Real key-view traversal plus Space and Return menu activation
  • Light and Dark appearance inspection with localized pop-up-button values
  • Full swift test (607 tests, 0 failures), swift build, release-helper preflights, and git diff --check
  • Packaging, signing, notarization, and final public-artifact checks remain part of the publication gate
